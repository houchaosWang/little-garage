# 小小维修站 — 学前学习兴趣引导APP设计文档

日期：2026-08-31
状态：已与家长确认全部设计决策，待实现规划

## 1. 背景与目标

- 用户：4-5岁男孩，喜欢赛车类动画（赛车总动员）、警车救援类动画（啦咘啦哆警长）、各类工程车辆。不认字。iPad使用经验几乎只有看视频，没有游戏操作经验。
- 问题：家庭现行"做任务换动画片时间"体系中，孩子从不主动选择做题类任务，家长担心形成厌学/畏学心理。
- 根因判断：交换体系把"学习"摆在了"换娱乐的代价"位置（过度合理化效应），强化了"学习=苦差事"的印象。
- 首要目标：修复心态——让孩子体验"学的过程本身是好玩的"。知识收获是副产品，不是首要KPI。
- 明确决策：本APP与动画片时间**完全脱钩**。不做任何"玩这个换看片"的机制。动画片时间由家长按固定作息另行管理。

## 2. 核心概念

孩子扮演维修站师傅。各种车辆客人上门求助，他动手帮忙修理；学习内容（数量、颜色、形状、逻辑等）完全藏在修车动作里。方向组合：

- 骨架：维修站循环（可无限随机重玩，学习密度高，开发成本低）
- 奖励层：养成收集（贴纸/零件装扮自己的爱车、朋友相册）
- 调味：救援剧情感（每位客人带一句小故事的求助开场白；完整剧集留待后续版本）

竞品不是其他游戏，而是"躺着看动画片"。因此整体感觉应接近"能自己操作的动画片"：角色驱动、语音驱动、交互极简。

## 3. 设计铁律

1. **不存在失败**：没有红叉、没有错误音效、没有倒计时、没有分数。做错时客人车友善引导（"嗯……我数一数，1、2、3……好像还差一个哦！"），直到成功，成功必然到来。
2. **权力反转**：他是被需要的师傅，车是求助者。"帮上忙"是这个年龄段男孩最强的驱动力之一。
3. **隐形难度自适应**：孩子永远处在"跳一跳够得着"的区间，感知不到"难度"概念，只感到自己越来越厉害（详见第7节）。
4. **零阅读依赖**：所有交互不需要认字（详见第10节）。
5. **无数值经济**：不做金币、商店、体力值。奖励是即时、具象、情感化的。
6. **无留存钩子**：无推送、无红点、无每日签到。打烊机制主动限制时长（详见第9节）。

## 4. 核心游戏循环

一单（一位客人）约2-4分钟：

1. 车库开门/主界面：爱车伙伴打招呼。门铃响，客人车进场。
2. 客人登场：随机生成（车型×颜色×表情×名字），说一句带剧情的求助语音（"我叫小蓝！马上要跑山路比赛，可是我的轮胎坏啦！"）。
3. 修理环节 ×2-3：每个环节是一个藏着学习点的微游戏（见第5节），环节间用车的反应串联。
4. 完工时刻：客人焕然一新、欢呼、鸣笛冲出车库，说谢谢（他的名字会被喊出来）。
5. 奖励掉落：1个贴纸或零件，可立即装到爱车上或存进收藏。
6. 回到主界面：下一位客人排队中；或去"我的车"页面玩装扮。

## 5. 修理微游戏与车型系统

### 微游戏基础类型（v1六类）

| 修车动作 | 学习点 | 交互 |
|---|---|---|
| 装轮胎/装货"装上N个" | 点数、数量对应、加减 | 拖拽到虚线位 |
| 加油"加到数字N" | 数字认读、数序 | 按住油枪，数字上涨，到位松手 |
| 换车灯/调漆"要一样的颜色" | 颜色辨认、混色 | 点选/拖拽 |
| 拧螺丝/换车窗 形状对孔 | 图形认知、复合图形 | 拖拽配对 |
| 换尾翼/云梯"要更大/更长的" | 大小、长短、多少比较 | 点选 |
| 洗车 划擦干净 | 无学习点，纯放松爽点 | 滑动擦拭 |

洗车类"纯爽环节"按约1:3比例穿插，控制学习密度、维持"这是玩"的感觉。

### 车型系统

- v1客人车型8种：赛车、警车、救护车、消防车、挖掘机、翻斗车、搅拌车、铲车。
- 车辆为模块化SVG拼装：底盘+车身+特征件（铲斗/滚筒/车斗/云梯/灯条）+配色+眼睛表情。新增车型边际成本低，后续可加吊车、洒水车、垃圾车、拖拉机等。
- 每种车型带"签名任务"绑定其特征件：翻斗车装石头（数数）、搅拌车调漆（混色）、挖掘机换铲斗（比大小）、消防车接云梯（比长短）、救护车清点药箱（点数）、警车对讲机（听指令）等。车型轮换保证同类玩法呈现常新。
- 全部为原创卡通形象（大眼睛拟人风格），不使用任何版权角色。
- 孩子的爱车：一辆专属座驾（默认小赛车），出现在主界面与装扮页。

## 6. 知识体系课程地图

七个领域，各约6级阶梯。入口低（当前能力立即成功），天花板通到幼小衔接水平：

| 领域 | 起步 | 天花板 |
|---|---|---|
| 数与量 | 点数1-4、按数取物 | 目测报数(subitizing)、序数"第几"、数的分解(4=2+2)、20以内实物加减 |
| 图形与空间 | 圆方三角配对 | 复合图形拼搭、立体件(球/圆柱)、上下左右方位、对称 |
| 逻辑与规律 | 按颜色二分类 | AB/ABB/ABC规律接龙、多维分类、序列排序、简单推理 |
| 颜色与观察 | 8种基础色 | 混色、深浅、两图找不同("找出哪里坏了") |
| 顺序与步骤 | 两步修车顺序 | 四步流程排序、听懂"先…再…然后…"多步指令 |
| 生活常识 | 车辆与职业配对 | 红绿灯规则、工具与用途、安全常识 |
| 语言识字(轻量) | 认自己的名字(维修师工牌) | 车牌认读常见字、高频字曝光。拼音/英语留待v2+ |

- 每单混搭不同领域的任务，保证广度轮换。
- 字形顺带曝光：语音指令同时在气泡中显示文字（如数字"4"既是听觉也是视觉目标）。

## 7. 难度引擎与VIP挑战

- 每个技能（领域×级别）独立记级，存本地。
- 升级：同技能连续2次无求助、无错误完成 → 悄悄升1级。
- 降级：同技能出现连续错误或求助 → 退半级（内部以0.5级粒度记录，出题按取整级别）。
- 出题：普通客人按当前级别出题；同单内不同环节可跨领域。
- 金头盔VIP客人：低频出现（约每6-10单一位），任务比当前水平高1级，**由孩子自己选择接或不接**；完成有加倍欢呼与限定贴纸。把挑战变成主动选择的荣誉。拒绝VIP无任何负面反馈。
- 家长可在家长角落查看各领域当前级别，并手动圈定级别上下限。
- 内容天花板保护：引擎升级封顶于当前版本已实装题库的最高级；触顶时家长角落提示"他已毕业，该更新内容啦"，避免出题超出题库范围。

## 8. 奖励与养成层

- 掉落物：贴纸（装饰类）与零件（喷漆色、轮毂、尾翼、车贴）。修完必掉1个，VIP掉限定款。
- 我的车库：给爱车喷漆、换轮毂、贴贴纸；点车有反应（眨眼、按喇叭、转圈）。装扮纯外观，无数值。
- 朋友相册：帮助过的客人存入相册；回头客再次上门会认出他（"是你呀！上次谢谢你！"）——用"被记住"制造情感黏性。
- 徽章（轻量）：同车型修满N辆获得该车型徽章（如"挖掘机大师"），仅展示用。

## 9. 打烊仪式与防沉迷

- 每日营业单量默认4单（约15分钟），家长角落可调（2-8单）。
- 最后一单完成：天色渐暗 → 客人道晚安 → 卷帘门落下 → 爱车打哈欠入睡 →"明天见！"。结束是剧情的一部分。
- 打烊后打开APP：安静的睡觉车库（嘘——大家在睡觉），无任何可玩内容。次日0点后自动开门；家长角落有当日加开1单的例外开关（应对特殊场合）。
- 无推送、无红点、无签到、无"连续登录"机制。
- 建议家长配合开启iOS"引导式访问"锁定应用（文档提示，非APP功能）。

## 10. 零阅读引导系统

1. 全语音指令：客人开口说需求；界面文字仅为顺带字形曝光。
2. 重听按钮：常驻大喇叭按钮，点击重播当前指令。
3. 演示小手：每个微游戏首次出现时，发光小手自动演示一遍完整操作；之后不再打扰。
4. 闲置援助：无操作约12秒 → 语音温柔重述 + 小手指向目标；再闲置 → 目标高亮脉动。
5. 视觉语法：可拖拽物轻微弹跳；目标位虚线圈+闪烁；正确放置有声光反馈。
6. 图标+语音导航：所有按钮按下时朗读自己的功能。

## 11. 技术方案

- 形态：PWA（网页应用）。iPad Safari打开 → 添加到主屏幕 → 全屏独立运行。
- 技术栈：原生HTML + SVG + CSS动画 + vanilla JavaScript（ES Modules），**零框架、零运行时依赖、零构建步骤**——浏览器直接运行源码。唯一的开发机脚本是语音批量生成（见第12节）。理由：家长独立维护成本最低、永不因依赖升级而坏。
- 渲染：DOM+SVG（车辆即SVG组件），动画用CSS transition/animation与Web Animations API。不用Canvas游戏引擎。
- 语音方案：所有台词为有限集合（固定短语+数字1-20+颜色+车型名+孩子名字）。开发机上用 edge-tts（微软晓晓/云希自然语音）预生成mp3打包进应用。数字等组合句由分段音频拼接。**不依赖** iOS SpeechSynthesis（音质差、时序不可控），仅作极端兜底。v2支持家长录音覆盖同名音频。
- 音效：短音效文件（叮、欢呼、喇叭等），Web Audio API播放。
- 音频解锁：iOS要求用户手势后才能出声 → 启动画面设计为"按门铃开始营业"，首次点击即完成音频解锁。
- 存储：进度/等级/贴纸/统计/设置存 localStorage（量小结构简单）；预留IndexedDB给v2家长录音。数据不出设备，无账号无服务器无采集。
- 离线：Service Worker 预缓存全部资源（HTML/JS/SVG/音频），首次加载后完全离线可用；联网时后台检查新版本，下次启动生效。
- 部署：GitHub Pages（家长已有GitHub账号）。更新流程：本地修改 → git push → Pages自动发布 → iPad联网启动时自动更新。若实测github.io访问不稳，迁移Cloudflare Pages（纯静态，方案不变）。
- 屏幕：横屏优先设计；检测到竖屏时显示"把iPad转过来"的图示动画。适配iPad各尺寸（安全区、@2x）。
- 音量/资源预算：全部资源目标 < 30MB（音频占大头），保证低配iPad流畅与快速缓存。

## 12. 架构分解

各模块单一职责、接口清晰、可独立测试：

- `core/rng.js`：带种子随机工具。
- `core/store.js`：读写localStorage的存档层（等级、贴纸、统计、设置），带版本迁移。
- `core/audio.js`：音频管理（预载、播放队列、语音拼接、静音处理）。
- `core/difficulty.js`：难度引擎（纯函数：输入历史表现 → 输出各技能当前级别与升降决策）。
- `core/taskgen.js`：出题器（纯函数：输入车型+技能级别 → 输出任务描述对象）。
- `vehicles/factory.js`：车辆工厂（车型模板+配色+表情 → SVG节点）；`vehicles/parts.js` 特征件库。
- `scenes/`：场景状态机（开门→接待→修理×N→完工→奖励→打烊），每个场景一个模块，统一生命周期接口（enter/exit/handleInput）。
- `games/`：六类微游戏，各自独立模块，实现统一接口（init(task)/onComplete回调），互不依赖。
- `ui/guide.js`：演示小手与闲置援助计时器。
- `parent/`：家长角落（长按3秒入口、观察面板、设置）。
- `sw.js`：Service Worker缓存与更新。
- `tools/gen-voice.py`（开发机脚本）：调用edge-tts批量生成台词mp3清单。

## 13. 错误处理与边界

- 音频加载失败：不阻塞游戏，视觉引导仍完整可玩；控制台记录。
- 存储写入失败/被清空：游戏可从零开始正常运行，不崩溃。
- 竖屏/分屏：显示旋转提示，暂停场景。
- 中途退出：任意时刻杀掉APP，重进回到主界面，不惩罚不丢奖励（当前单作废不记错误）。
- 日期回拨/时区：打烊判定用本地日期字符串，异常时宽松处理（宁可多玩一单，不误锁）。

## 14. 测试策略

- 纯逻辑单测（node直跑，无框架）：difficulty.js（升降级边界）、taskgen.js（各级别出题合法性：数量范围、答案存在、干扰项不歧义）、store.js（迁移与损坏数据恢复）。
- 视觉/交互：开发中用浏览器触屏模拟预览各场景；发布前真机iPad过一遍首次引导全流程。
- 真实用户测试：孩子试玩即测试。家长角落的统计（求助率、错误率、重玩率）就是评估工具。

## 15. v1范围（试水版）

包含：核心循环、8车型、六类微游戏、七领域各前2-3级题库、难度引擎、贴纸+爱车装扮（喷漆/轮毂/贴纸）、朋友相册、VIP客人、打烊仪式、零阅读引导、家长角落（观察面板+单量设置+级别范围）、PWA离线+Pages部署。

不包含（后续路线）：救援剧集特别篇（v2）、家长录音覆盖（v2）、更多车型包（随时可加）、徽章墙扩展、拼音/英语领域（v3）、多孩子档案。

## 16. 成功标准

- 行为信号（2-4周观察）：他主动要求打开这个APP，频率不低于要求看动画片的一半；打烊时能接受结束、无激烈哭闹。
- 数据信号（家长角落）：求助率随时间下降；至少3个领域升级≥1级；重玩最多的环节即他的兴趣点（反馈给后续内容设计）。
- 心态信号（最重要，家长主观判断）：提到"去修车"时是期待的；在现实中开始主动数东西、认颜色形状。

## 17. 非目标

- 不做题库刷题模式、不做成绩单/排名/星级评分。
- 不联网账号、不采集任何数据、无广告、无内购。
- 不使用任何版权动画形象。
- 不追求"每天玩很久"——打烊机制的目标恰恰相反。
